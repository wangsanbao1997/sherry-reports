# 實價登錄監測快報 v2

自動監測彰化縣「溪湖鎮、埔心鄉、埤頭鄉、埔鹽鄉、秀水鄉」五鄉鎮的
內政部實價登錄新增交易，產出 PDF（橫式明細表＋圖表頁）＋ 手機版 HTML 雙報告，寄到指定信箱。

## 報告格式

- **明細表**：橫式 A4，欄位為「鄉鎮｜類別｜交易標的｜地段/門牌｜交易日期｜
  總價(萬)｜單價(萬/坪)｜土地(坪)｜建物(坪)｜使用分區ｨ建物型態」，
  非常規交易與價格偏離會在地段/門牌欄下方標紅備註。
- **圖表頁**：獨立一頁，**每個鄉鎮各自兩張圖**（土地成交件數折線圖、房屋成交
  件數折線圖），共五鄉鎮最多 10 張圖，彼此不混畫在同一張圖表上。
  X 軸固定為「前三個完整月份」（例如當前為 7 月 → 顯示 4、5、6 月，不含當月）；
  某月無交易則顯示為 0，全三個月皆無交易的圖才會略過。

產出一份完整清單寄給妳；**之後每次執行只會通知「新增」的部分**。

## 排程時間

| 時段（台灣時間） | 觸發時機 | 無新增時是否寄信 |
|---|---|---|
| 每月 1、11、21 日 14:00 | 主要執行 | 會寄「系統正常」通知 |
| 每月 1、11、21 日 18:00 | 補跑（防政府延後發布） | 不寄 |
| 每月 2、12、22 日 14:00 | 次日補跑（防漏抓） | 不寄 |

內政部實價登錄資料約每旬（1、11、21 日）發布最新季度，多數日子會是「無新增」，
更新日當天會收到完整新增清單。

也可以隨時到 Actions 頁面手動 `Run workflow` 立即執行一次。

## 系統設計重點

- **假 200 偵測**：政府伺服器在資料尚未發布時，有時會回傳 HTTP 200 但內容是
  HTML 錯誤頁而非 ZIP，系統以 ZIP magic bytes 判斷，並自動重試遞增等待。
- **同時抓本季＋上季**：避免補登記交易（買賣完成後補登記可能晚於當季）被漏掉。
- **依使用分區分開統計中位數**：農地與建地混算會讓中位數嚴重失真
  （實測曾造成建地被誤標 +633% 偏離），系統依住宅／商業／農地／其他分開計算。
- **非常規交易排除**：親友交易、拍賣、債務抵償等不納入中位數基準。
- **樣本不足不判斷**：同鄉鎮同類別歷史樣本少於 3 筆時，標記為
  「【假設】樣本不足未判斷」，不會強行給出偏離結論。
- **三層事實標記**：【事實】（落於正常區間）／【推估】（偏離區域中位數）／
  【假設】（樣本不足或非常規交易，無法判斷）。
- **法規用詞**：全系統避免使用「估價」「鑑價」等具法律意涵字眼，
  一律用「行情觀察」「交易資訊整理」，並在報告內附免責聲明。
- **失敗自動告警**：執行過程若發生例外，會自動寄一封錯誤警告信，
  附上完整錯誤訊息，方便排查。

## 常用調整

- **改監測鄉鎮**：`lvr/config.py` 的 `TARGET_TOWNS`
  （同縣內直接改；跨縣要同時改 `COUNTY_PREFIX`，彰化＝`n`）
- **偏離門檻**：`lvr/config.py` 的 `DEVIATION_THRESHOLD`（預設 0.30，即 ±30%）
- **改排程時間**：`.github/workflows/lvr.yml` 的 `cron`（UTC；台灣時間 −8 小時）
- **無新增時要不要寄信**：workflow 內的 `send_empty` 判斷邏輯

## 免責聲明

本系統輸出為內政部實價登錄公開資料之整理與行情分析，
非「不動產估價師法」所稱之估價報告，亦非正式鑑價文件，
僅供參考，實際交易應以買賣雙方協議及專業估價為準。
